# 先看书还是先做题？（75 s）

「六条视频」里的第 1 条（`six/plan.md` 第 1 条，`six-videos` 分支）：画法 A（扁平插画），舞台是答题闯关台。
一个成年人比例的小人（`src/figure.js`，从 `kit/figure.js` 原样复制，按 plan.md 的规定不直接引用 `kit/`），每一帧都在；他站着、走着、拍抢答器、抽题卡、写、拿荧光笔圈，不坐在桌前。
节奏按「睡还是背」的骨架（lessons 结论 13）：第 0 帧两行问题 + 他已经在动 + 重击音，2.11 s 揭晓 1（停 4 拍），3.98 s 揭晓 2，4.92 s 打勾，8 s 答案，12.4 s 证据卡，15 / 30 / 45 s 三关，60–75 s 边演边出总结，75 s 直接结束。
1920×1080 / 30 fps / 75.000 s，H.264 + AAC，14.5 MB。只有音效、没有配乐，按 128 BPM 卡点；画面上没有点赞 / 收藏 / 关注 / 评论提示。

## 数据来源（都取自 `six/facts/01_quiz_first.md`，那份核对表读过原文）
- **Pan & Sana 2021**，《JEP: Applied》27(2):237–257，实验 4（表 1、表 2）：美国本科生读同一篇百科短文，做同一套 8 道四选一题，只换先后。先做题组第一次只对 31%（瞎蒙 25%），先看书组读完再做对 57%；48 小时后再考：75% 对 53%。每组 28–34 人。开场的两次揭晓都用这个实验，所以画面写「先看书」，不写「一直看书」。
- **St. Hilaire, Chan & Ahn 2024**，《Psychonomic Bulletin & Review》31(2):411–441：预注册元分析，76 份文献、7,902 人；被问到的内容 g = 0.54，没被问到的 g = 0.04。另一项元分析 King-Shepard 等 2025（g = .66 / .01）和它有 35 份文献重叠，片里只说「两项元分析」，不说「两次独立验证」。
- **Richland, Kornell & Kao 2009**，《JEP: Applied》15(3):243–257，实验 4：先做题组 2 分钟答 5 题、再读 8 分钟，对照组读满 10 分钟；先猜的平均只对 10%；一周后 55% 对 45%，只算预测时答错的题（每组 79 人）。对照组从头到尾没做题，所以 ② 写「一直看书」。例题「番茄汁在 Mr. I 眼里是什么颜色？」出自论文附录 A，文中答案是黑色；其余几道题论文没给，片里画成空行。
- **St. Hilaire & Carpenter 2020**，《JEP: Applied》26(4):705–716，实验 3：大学生看 30 分钟视频课，看课时写下了答案的题，终测 84%，对照 54%；没找到答案的题 50%，和对照一样（条件分析，不是随机对照）。
- **ManyClasses 2**（PsyArXiv 预印本 v2，2025）：30 个真实班级、1,571 人，73.7% 对 68.8%，约 5 个百分点。
- 没说的话（核对表第 5 节）：不说「整章都记得更好」「做题能代替看书」「错得越多越好」「成绩提高 20 分」。

## 重新出片
```bash
bash tools/build.sh                                         # 约 1.5 分钟：音效 -> 逐帧 -> MP4 -> verify -> 第 0 帧 -> 备用封面
node tools/render.mjs --lint                                # 每 0.25 s 查一遍：文字出画 / 互相压住、道具出画（都应为 0）；小于 34 px 的字、道具叠在一起、挡住他的头只列出来
node tools/sheet.mjs --mp4 out/先看书还是先做题_75s_1080p.mp4   # 分镜预览（--times 0,1.5,3 只截这几个时间点，输出 build/quick.png）
.venv/bin/python tools/verify.py out/先看书还是先做题_75s_1080p.mp4  # 时长、尺寸、响度、真峰值、音效对拍、画面卡拍、抖动
node tools/render.mjs --stills 0,2.2,4.5                    # 只看几帧，输出到 build/stills/
node tools/render.mjs --covers                              # 只出备用封面（会查竖封面那块的留白和左下角）
```
- 第一次运行会在这里建 `.venv`，装 numpy 和 imageio-ffmpeg（自带 ffmpeg）。还需要 Node 18 以上和 Chromium：Kiro 沙箱里都有，脚本会自动找到；在别的电脑上，先在这个目录 `npm i playwright-core`，再把 `CHROME_EXE` 指向本机的 Chrome。
- 画面：`src/scene.js`（标题、开场、先猜再读、逐帧总入口）、`src/sections.js`（三关和照着做）、`src/hero.js`（小人的姿势时间线：关键帧 `PT()`，手用两节 IK `armTo()` 真的够到按钮、题卡和书页）、`src/props.js`（舞台和道具：题卡架、抢答器、记分牌、跑马灯、题库盒、例题卡、大书页、荧光笔、吊屏、翻牌）。时间都按拍写。
- 音效：`tools/audio.py`，cue 表在 `cues()`，共 167 个；新做的音效有抢答器的「错」、拍按钮、脚步、荧光笔；第 0 帧一声重击；混音后按响度（BS.1770）统一到 -18.4 LUFS，和前几期一样。
- 小人：`src/figure.js` 和 `kit/figure.js`（`six-videos` 分支，提交 c2491b8）一字不差；这期加的姿势（拍按钮、抽卡、写、圈、耸肩接着写）都在 `src/hero.js`，没改骨架。`src/lib.js` 来自 `bedtime_words/src/lib.js`，只改了章节名，加了道具的 lint 框（`lintPanel`）。`tools/` 来自 `bedtime_words/tools/`，`verify.py` 是这期新写的。

## 验证（`tools/verify.py` 和 lint 的结果）
- 75.000 s，1920×1080，30 fps，14.5 MB；2250 帧每一帧都有小人（`build/frame_check.json`）
- 响度 -18.4 LUFS，真峰值 -2.4 dBTP；61 个主要音效在成片音轨里找到起音，中位偏差 -0.5 ms（慢起音的翻页、涂写声测出来晚 30 ms 左右，混音里都在拍上）
- 97 个画面事件，80% 落在半拍网格 2 帧以内；抖动：静止区域在拍点上的额外变化平均 0.24 灰度（< 1.0，不抖）
- lint：文字出画 0、文字互相压住 0、道具出画 0；小于 34 px 的有 55 处，都是来源、英文副标题、章节名，以及缩小后的题卡
