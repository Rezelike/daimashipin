# 单词卡分小叠背更好？（75 s，`six/plan.md` 第 6 条）

「一口气做 6 条」那一批的第 6 条：小人用画法 B（霓虹线条），舞台是一张发牌桌：他像荷官一样站在桌子后面，桌子挡住腿，手伸到桌面上洗牌、发牌、翻牌。一个成年人比例的小人，全程站着、走着、指着，不坐、不写作业（Skill 2.5）；小人从 `kit/figure.js`（`six-videos` 分支）复制到 `src/figure.js`，没有引用 `kit/`，也没改它。
结构和拍点照「睡还是背」（lessons 结论 13），道具和每一屏都是这期自己的（Skill 2.3）：绒面牌桌和桌面上印的字、平躺 / 立着 / 飞着的发光单词卡、能看见一张张卡边的牌叠、两手之间飞的一串牌（洗牌）、会翻面的大立牌（「我估计能记住」翻成「考试答对」）、带角标的卡片做 ①②③ 和每步的标题、桌上的日期立牌、对话气泡、弃牌盒、绕牌叠一圈的箭头、58 张小卡代表 58 个人。没有用前几期和这批另外 5 条的柱子、挂钟、计时环、闹钟、日历、HUD 面板、描边编号、清单表、单词卡网格、窗户、记分牌、旗子、声波块、水池和房子。画面上没有收藏、点赞、关注、评论提示。

## 数据来源（数字只从 `six/facts/06_flashcards.md` 取，`six-videos` 分支）
- **Kornell 2009**，《Applied Cognitive Psychology》23(9):1297–1317，doi 10.1002/acp.1537。UCLA 学生，实验 1 / 2 / 3 各 20 / 25 / 25 人，网页上的电子卡，40 对 GRE 难词 → 同义词（例：effulgent → brilliant，附录 p. 1317）；每人两种都用、各 20 张：一大叠 = 1 叠 20 张，四小叠 = 4 叠 × 5 张，一叠背完再换下一叠。
  - 开头（实验 3）：第 1 天学完的估计 小叠 66%、大叠 51%（24 人，p. 1308）；第 5 天全部复习两遍，第 6 天考试 大叠 65%、小叠 34%（p. 1307）。三个实验合计 70 人里 63 人大叠分更高（p. 1310）。
  - 12.4 s 小卡：第一轮学完，58 个两种估计不一样的人里 42 人（72%）觉得小叠记得更多（摘要；p. 1310）。分母是 58，不是 70；只是第一轮学完的看法（后面几天就没差别了）。
  - ①（实验 1）：只学一次，每张 4 遍，约 24 小时后考：49% vs 36%；每张卡累计用时 22.6 vs 22.2 秒，没差别。
  - ②（实验 2）：分 4 天学，大叠每天 2 遍，小叠每天换一叠、当天 8 遍，每张卡都是 8 遍；第 5 天考：54% vs 21%；最后一天才背的那叠 34%（p. 1304）。
- **Kornell & Bjork 2008**，《Memory》16(2):125–136，doi 10.1080/09658210701763899。③ 的数：实验 4（表 1，p. 133），40 对英语–斯瓦希里语单词，电脑在答对 1 次后自动把卡抽走的那份 21%，同一批人不抽的那份 44%，只剩 8 人（p < .05）。片里和简介里都写了「只有 8 人」。
- 「先说出答案再翻」是用卡的人通常的做法（Kornell 2009 p. 1298；K&B 2008 实验 2 里 80% 的人自报这样做，p. 130），两篇都没有单独检验它的效果：片里 52.3 s 照写。

## 和 `six/plan.md` 第 6 条不一样的地方
- 5.39 s：分镜写「70 人里 63 人大叠分更高」，片里是「三个实验 70 人里，63 人大叠分更高」：65% vs 34% 只属于实验 3，63/70 是三个实验合计（事实核对表第 3 节要求标清楚）。
- 12.4 s 小卡：分镜写「58 个给出判断的人里 42 个（72%）觉得小叠更好」，片里是「估计有高低的 58 人里，42 人（72%）觉得小叠记得更多」：这 58 人是给两种卡估了不同分数的人，他们估的是能记住几成；加了 58 张小卡、42 张亮起。
- ①：分镜只有大叠那一排，片里在下面加了一排四小叠的顺序（同一张隔 4 张就回来），这样「隔 19 张」有个对比。
- ②：分镜写「桌边日期牌翻 4 天，每天他把整叠过两遍」，片里还加了四小叠：每天只亮一叠、当天转 8 圈（×8），这样 54% 和 21% 两边都在画面上。
- ③：加了一行小字「先说再翻：常见做法，这两项研究没单独测过」（事实核对表第 4 节）。
- 结尾小字：分镜写「仅供参考：每个实验 20–25 名 UCLA 学生，隔一天考」，片里是「仅供参考：每个实验 20–25 名美国大学生，电脑上的单词卡，学完隔一天考」+「抽卡那项（Kornell & Bjork 2008）只有 8 人」：纸质卡、背单词 app 没测过；③ 的数来自另一项研究、人更少。
- 封面提示词用实验 3 的 34% / 65%，左边四小叠、右边一大叠（从差到好）。

## 重新出片
```bash
bash tools/build.sh                                                 # 约 2 分钟：音效 -> 逐帧 -> MP4 -> 第 0 帧 -> 备用封面
.venv/bin/python tools/verify.py out/单词卡分小叠背更好_75s_1080p.mp4   # 文件、响度、音效卡拍、段落切换、画面卡拍、画面抖不抖、小人在不在（数字）
node tools/render.mjs --lint                                        # 每 0.25 s 查一遍文字：出画、互相压住（应为 0），小于 34 px 的列出来（--range 0,15 只查一段）
node tools/sheet.mjs --mp4 out/单词卡分小叠背更好_75s_1080p.mp4        # 分镜预览（--times 0,1.5,3 只截这几个时间点，输出 build/quick.png）
node tools/render.mjs --stills 0,2.2,4.5                            # 只看几帧，输出到 build/stills/
node tools/render.mjs --covers                                      # 只出备用封面（会查竖封面那块的留白和左下角）
```
- 第一次运行会在这里建 `.venv`，装 numpy 和 imageio-ffmpeg（自带 ffmpeg）。还需要 Node 18 以上和 Chromium：Kiro 沙箱里都有，脚本会自动找到；在别的电脑上，先在这个目录 `npm i playwright-core`，再把 `CHROME_EXE` 指向本机的 Chrome。
- 画面：`src/scene.js`（开头的两种摆法和大立牌、8–15 s 合成一大叠和小卡、他每一拍的位置和姿势、画面顺序：小人只画桌沿以上 → 桌子 → 伸到桌面上的手臂 → 手里的牌），`src/sections.js`（①②③ 和照着做），时间都按拍写；道具在 `src/props.js`（`drawTable` 牌桌、`flatCard` / `deckStack` 桌上的卡和牌叠、`uprightCard` 立着能翻面的卡、`cardSpring` 洗牌、`placard` 大立牌、`indexCard` / `tagCard` 角标卡、`dayStand` 日期立牌、`speechBubble`、`discardTray`、`loopArrow` / `hopArrow`、`voteStrip`）；小人在 `src/figure.js`（画法 `style: 'B'`，和 kit 里的一样）。
- 音效：`tools/audio.py`，cue 表在 `cues()`，261 个；这期新合成的有洗牌（`riffle`：一串卡片弹出的声音）、发牌（`deal_snap`）、卡在桌面上滑（`card_slide`）、翻牌（`card_flip`）、码齐（`tap_deck`）；说答案用的是合成的元音音节（`voice`），不是真人说话，也没有歌。第 0 帧一声重击，混音前软削波 1.8，按响度（BS.1770）统一到 -18.4 LUFS。
- 验证（`tools/verify.py`，从 `read_aloud/` 复制，加了 `nap_length/` 那样的「小人在不在」一行）。这次的结果：75.000 s、1920×1080、30 fps、11.4 MB；-18.4 LUFS，真峰值 -5.7 dBTP；72 个响的音效在成片里找到起音，中位数偏拍 -0.5 ms，90% 在 1.4 ms 以内；15 / 30 / 45 / 60 s 的段落切换离小节线都是 0 ms（8.0 s 是标题翻面，+31 ms）；画面里 124 处变化的起点，90% 落在半拍网格 ±2 帧内；拍上静止区域的额外变化平均 0.29 灰度（< 1.0，不抖；最大的 4 个值正好是 15 / 30 / 45 / 60 s 四个硬切，去掉它们平均 0.06）；没有哪一帧缺小人。
