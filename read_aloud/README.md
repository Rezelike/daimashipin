# 背书要读出声吗？（75 s，`six/plan.md` 第 3 条）

「一口气做 6 条」那一批的第 3 条：小人用画法 B（霓虹线条），舞台是声音：念出声的词变成发光的实心块，默读的词只是虚线框，地平线是一条声波，每念出一个词就荡开一圈。一个成年人比例的小人，全程站着、走着、指着、跳着，不坐、不写作业（Skill 2.5）；小人从 `kit/figure.js`（`six-videos` 分支）复制到 `src/figure.js`，没有引用 `kit/`。
结构和拍点照「睡还是背」（lessons 结论 13），道具和每一屏都是这期自己的（Skill 2.3）：单词块堆成的「认得出」栏、悬空的纸、复习笔记和光笔、四行读法、两个托盘、三段式流程条、卡拉 OK 式的标题（虚线字一拍拍填成实心，像把字念出来）。没有用前几期的柱子、挂钟、计时环、闹钟、日历、HUD 面板、描边编号、清单表、单词卡网格和窗户。画面上没有收藏、点赞、关注、评论提示。
1920×1080 / 30 fps / 75.000 s，H.264 + AAC 256 kb/s，15.9 MB。只有音效、没有配乐，按 128 BPM 卡点；小人在每一帧里。

## 数据来源（数字只从 `six/facts/03_read_aloud.md` 取；Roberts 2024 又对了一遍原文表 1）
- **MacLeod、Gopie、Hourihan、Neary、Ozubko 2010**，《JEP: Learning, Memory, and Cognition》36(3):671–685：实验 1A+1B（滑铁卢大学 44 名学生），同一张表 80 个英语名词，一半念出声、一半默读，之后做「见过 / 没见过」：默读的认出 59.8%，念出声的 76.0%（表 1）。这是认得出的比例（命中率），高 16 个百分点，片里不说「多记住 16%」。
- **Icht、Mama、Algom 2014**，《Frontiers in Psychology》5:886：以色列 Ariel 大学 60 名学生；八成的词念出声的那组，默读的认出 63.1%，念出声的 65.3%，不显著。
- **Forrin、MacLeod 2018**，《Memory》26(4):574–579：75 名学生，自己念 77% > 听自己的录音 74% > 听别人念 69% > 默读 65%（图 1 柱里印的数）。
- **Forrin、MacLeod、Ozubko 2012**，《Memory & Cognition》40(7):1046–1055：实验 2C 出声 66.1% > 小声 56.7% > 默读 42.8%；实验 2B 只动嘴 56.1% > 默读 43.3%（片里只写「比默读好」，没放这个数）。
- **Roberts 等 2024**，《Memory & Cognition》52(1):57–72，表 1：用实验 2（64 名成年人，网上招募的美国人 + 澳大利亚 Flinders 大学的学生），记忆题 出声 81% / 默读 74%，理解题 82% / 81%；作者原话：实验 2 没能证实出声帮理解，只帮记忆。
- 「挑重点念」是 MacLeod 2010（p. 681）和 Ozubko 2012（p. 724）的建议，没被直接测过：片里照写。

## 和 `six/plan.md` 第 3 条不一样的地方
- ③ 的数：分镜写的是「记忆题 81% vs 72%，理解题没差」。81 vs 72 是 Roberts 2024 的实验 1，而实验 1 的理解题其实有差（80 vs 74，作者说证据弱）；改用实验 2 的一组：记忆题 81 vs 74，理解题 82 vs 81，同一个实验，「理解题差不多」也成立。
- 结尾小字：分镜写「加拿大、以色列大学生……几分钟到一周内的测验」。实验 2 的人有一部分是网上招募的成年人，片里也没有放隔一周的数，所以改成「国外的大学生和成年人；单词和英文短文；都是学完当场测」。
- 开头：分镜写同两列「虚线框全变实心」。做成了左右两组栏：左边一半念（60 / 76），右边几乎全念（63 / 65），这样「挑着念」的勾和「全念：差不多」各有自己的一组；「虚线框变实心」放在念词那一下：每个词都先是虚线框，念出声时才填实。
- 12.4 s 小卡的标题写「同一批单词，哪种学法认得出最多？」，和其他几处一样用「认得出」。

## 重新出片
```bash
bash tools/build.sh                                            # 约 2 分钟：音效 -> 逐帧 -> MP4 -> 第 0 帧 -> 备用封面
.venv/bin/python tools/verify.py out/背书要读出声吗_75s_1080p.mp4   # 文件、响度、音效卡拍、段落切换、画面卡拍、画面抖不抖（数字）
node tools/render.mjs --lint                                   # 每 0.25 s 查一遍文字：出画、互相压住（应为 0），小于 34 px 的列出来（--range 0,15 只查一段）
node tools/sheet.mjs --mp4 out/背书要读出声吗_75s_1080p.mp4       # 分镜预览（--times 0,1.5,3 只截这几个时间点，输出 build/quick.png；--extra 图片 说明 再加一张）
node tools/render.mjs --stills 0,2.2,4.5                       # 只看几帧，输出到 build/stills/
node tools/render.mjs --covers                                 # 只出备用封面（会查竖封面那块的留白和左下角）
```
- 第一次运行会在这里建 `.venv`，装 numpy 和 imageio-ffmpeg（自带 ffmpeg）。还需要 Node 18 以上和 Chromium：Kiro 沙箱里都有，脚本会自动找到；在别的电脑上，先在这个目录 `npm i playwright-core`，再把 `CHROME_EXE` 指向本机的 Chrome。
- 画面：`src/scene.js`（开场的两组栏和飞行的词、8–15 s 的纸和小卡、小人每一拍的姿势），`src/sections.js`（①②③ 和照着做），时间都按拍写；道具在 `src/props.js`（`wordBlock` 实心块 / 虚线框、`recogColumn` 认得出栏、`soundRings`、`lightPen` / `penLoop`、`karaoke` 标题）；小人在 `src/figure.js`（画法 `style: 'B'`）。
- 音效：`tools/audio.py`，cue 表在 `cues()`，217 个；念词声是合成的元音音节（`voice`、`whisper`、`lip`），不是真人说话，也没有歌。第 0 帧一声重击（-2 dB，这期音效比上期稀，重击原来决定了峰值），混音前软削波 1.8，按响度（BS.1770）统一到 -18.4 LUFS。音频用 256 kb/s：192 kb/s 时编码器在 0.1 s 处冲到 +0.2 dBTP，256 kb/s 时 -3.8 dBTP。
- 验证（`tools/verify.py`，做法同 `music_study/tools/verify.py`，加了文件、响度和段落切换三项）。这次的结果：75.000 s、1920×1080、30 fps、15.9 MB；-18.4 LUFS，真峰值 -3.8 dBTP；60 个响的音效在成片里找到起音，中位数偏拍 -0.5 ms，90% 在 1.1 ms 以内；15 / 30 / 45 / 60 s 的段落切换离小节线 0 / 0 / 0 / -67 ms（8.0 s 是标题翻转，+31 ms）；画面里 102 处变化的起点，89% 落在半拍网格 ±2 帧内；拍上静止区域的额外变化平均 0.09 灰度（< 1.0，不抖）。
