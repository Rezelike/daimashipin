# 边听歌边背书？（75 s）

不是睡觉题的一期，结构照「睡还是背」（lessons 结论 13）：同一套渲染（Canvas + numpy）、两个小人、背景、配色和音效做法，128 BPM，揭晓时间和前两期一样。底子是 `bedtime_words/`，道具和每一屏都是这期自己设计的（Skill 2.3）：头戴式耳机（耳罩颜色就是正在放的东西：粉色带词的歌、绿色纯音乐、灰色没放）、桌上的手机、音符、歌词气泡、默写纸、开场的播放条、「正在播放」标题卡、播放列表、专辑封面、自评滑块、四个打击垫、音量条、口算题和答对率屏、任务牌、三路调音台。没有用前几期的柱子、挂钟、计时环、闹钟、日历、HUD 面板、清单表，也没有用「背单词」的单词卡和窗户。画面上没有收藏、点赞、关注提示，也没有真歌，歌名一个都不出现。
1920×1080 / 30 fps / 75.000 s，H.264 + AAC，16.8 MB。只有音效、没有配乐，按 128 BPM 卡点；男孩在每一帧里。开场 0–2.11 s 男孩耳机里漏出很轻的合成节奏（踩镲 + 闷底鼓，没有旋律和人声），揭晓 1 那一拍停掉。

## 数据来源（都对过原文）
- **Souza & Barbosa 2023**，《Journal of Cognition》6(1): 24，doi 10.5334/joc.273：葡萄牙波尔图大学的心理系学生在线做实验，同一批人分别在安静、lo-fi 纯音乐、葡萄牙语流行歌（带词）下做 4 种任务。记词、记图时只在背的时候放音乐，默写时不放。下面的平均数是用作者公开的原始数据（OSF xcv6e）按论文的排除规则重算的，论文表 1 的 12 个效应量全部对得上，和图 3–6 的平均点一致：
  - 背 20 个词（113 人）：安静 8.39 个，纯音乐 7.94 个，带词的歌 7.37 个。带词的歌比安静少记约 1 个（d = −0.32，可信）；纯音乐和安静分不出来（d = −0.16，BF = 0.33），和带词的歌也分不出来（BF = 0.84）。所以片里写「差得不明显」，不写「追平」
  - 记图（118 人）：带词的歌 d = −0.33，可信；纯音乐 d = −0.23，说不清
  - 读句子（原始数据里 114 人）：安静 93.9%，纯音乐 94.7%，带词的歌 92.8%。带词的歌比安静差 d = −0.19，不可信（BF = 0.70）；比纯音乐差 d = −0.31，可信。所以任务牌上写「比纯音乐差」
  - 算术（106 人）：69.1% / 68.4% / 67.5%，d = −0.11，证据偏向没有影响（BF = 0.21）。摘要里「算术 d = −.19」是笔误，−0.19 是读句子的数
  - 自评（−10 到 +10，和安静比）：读句子后纯音乐平均 +2.3（63% 打正分），记图后 +1.3，背词后 −0.07；带词的歌在四种任务后都是负的（−1.4 到 −2.9）。所以片里说「读完」大家觉得纯音乐有一点帮助
- **Vasilev, Kirkby & Angele 2018**，《Perspectives on Psychological Science》13(5):567–597：65 项研究的贝叶斯元分析。阅读理解：所有声音 g = −0.21，噪音 −0.17，说话声 −0.26，音乐 −0.19；影响最大的是带词的歌（−0.35）和听得懂的说话声（−0.34），带词的歌比纯音乐更伤。这是「读书时别听带词的歌」的主要依据（Souza 的读句子只和纯音乐比出了差别）
- **Perham & Vizard 2011**，《Applied Cognitive Psychology》25(4):625–631：25 名大学生按顺序记 8 个字母；自己带来的喜欢的歌和讨厌的重金属一样差，都比安静差
- **Perham & Currie 2014**，《Applied Cognitive Psychology》28:279–284：30 名大学生读文章答题；喜欢的歌和讨厌的歌（都带词）一样差（约 37% 答对），安静约 61%，纯音乐约 55%，和安静差不多（数从论文的矢量图里读）
- **Thompson, Schellenberg & Letnic 2012**，《Psychology of Music》40(6):700–708：25 名大学生边听莫扎特的钢琴奏鸣曲边读文章，快 150 / 慢 110 拍每分钟 × 大声 72.4 / 小声 60 分贝；只有又快又响那组明显变差（6 题答对 1.95 题，安静的对照组 2.77 题），只快或只响都没事。所以画面写「别又快又响」，不说「纯音乐都没事」
- **Sun 等 2024**，《Frontiers in Psychology》15:1363562：山东 90 名大学生，6 组每组 15 人，判断题；歌词和文章同一种语言时最伤，平时就边听边学的人受影响小些。有一格正确率 0.30，低于瞎猜的 0.5，所以只当例子提一句，不用它的数，也不写歌名

## 重新出片
```bash
bash tools/build.sh                                         # 约 3 分钟：音效 -> 逐帧 -> MP4 -> 第 0 帧 -> 备用封面
.venv/bin/python tools/verify.py out/边听歌边背书_75s_1080p.mp4   # 音效卡拍、画面卡拍、画面抖不抖（数字）
node tools/render.mjs --lint                                # 每 0.25 s 查一遍：文字出画、互相压住；面板出画、互相压住、字压在小人头上；小于 34 px 的列出来
node tools/sheet.mjs --mp4 out/边听歌边背书_75s_1080p.mp4      # 分镜预览（--times 0,1.5,3 只截这几个时间点，输出 build/quick.png；--extra 图片 加一张）
node tools/render.mjs --stills 0,2.2,4.5                    # 只看几帧，输出到 build/stills/
node tools/render.mjs --covers                              # 只出备用封面（会查竖封面那块的留白和左下角）
```
- 第一次运行会在这里建 `.venv`，装 numpy 和 imageio-ffmpeg（自带 ffmpeg）。还需要 Node 18 以上和 Chromium：Kiro 沙箱里都有，脚本会自动找到；在别的电脑上，先在这个目录 `npm i playwright-core`，再把 `CHROME_EXE` 指向本机的 Chrome。
- 画面：`src/scene.js`（开场：飞进脑袋的词、歌词气泡、默写纸和三个数；关掉歌词：播放列表、证据卡），`src/sections.js`（①②③ 和照着做的调音台），时间都按拍写。耳机（戴着 / 挂在脖子上）在 `src/kid.js`（`phones`、`neck`、`phonesColor`），什么时候放什么在 `scene.js` 的 `musicMode()`；新道具在 `src/props.js`。
- 音效：`tools/audio.py`，cue 表在 `cues()`，241 个；耳机漏音是 `leak()`，比整体响度低 20 LU（`LEAK_LU`），声像偏右（男孩那边），2.11 s 停。混音后按响度（BS.1770）统一到 -18.4 LUFS，和前几期一样。成片测得 -18.4 LUFS，峰值 -1.6 dBFS；漏音 -38.4 LUFS。这期的音效比上期稀，软削波从 1.3 调到 1.8（`DRIVE`），峰值才压到 -1.5 dBFS 以下。
- 验证（`tools/verify.py`，这期新加的）：52 个响的音效在成片里找到起音，中位数偏拍 -0.5 ms，90% 在 8.8 ms 以内；画面里 102 处变化的起点，94% 落在半拍网格 ±2 帧内；拍上静止区域的额外变化平均 0.06 灰度（< 1.0，不抖）。
